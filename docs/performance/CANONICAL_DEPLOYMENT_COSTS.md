## Reproduction

Use Linux (including WSL) and the locked Python 3.14 project environment. Stop
test workers, profiling, coverage and other validation before running. An output
directory must not already exist. For a one-process pilot:

```bash
uv sync --frozen
uv run --no-sync python scripts/measure_canonical_deployment_costs.py \
  --output /tmp/canonical-cost-pilot --processes 1 --repeats 1 \
  --wall-seconds 600 --cpu-seconds 1200 \
  --host-note 'Describe host, WSL allocation and other known contention here.'
```

Select the campaign size from the pilot's actual cost. A suggested campaign is
three sequential fresh processes, one iteration each, followed by a component
pass in each process. Use `--repeats 2` or more to additionally sample warmed
repeats of `measure`; the selected one-iteration campaign does not measure them:

```bash
uv run --no-sync python scripts/measure_canonical_deployment_costs.py \
  --output /tmp/canonical-cost-campaign --processes 3 --repeats 1 --components \
  --wall-seconds 1801 --cpu-seconds 3600 \
  --host-note 'Record the actual host and isolation conditions.'
```

The campaign admits at most an eight-CPU-hour declared ceiling; defaults are one
hour wall and two CPU hours. The supervisor polls every 0.1 seconds, stops on the
first detected exhausted campaign limit, kills the worker process group, and
retains partial output. Polling can overshoot a limit; the evidence records actual
elapsed and CPU use. A failed worker or mismatched report stops the campaign too.
There are no retries or discarded warmups. The canonical runner's existing
eleven-decision/120-second cooperative recipe limit remains unchanged and is
distinct from these operator limits and the normal 180-second serial smoke gate.

## Timing boundaries and cache state

| Measurement | Inclusive boundary / prepared input |
|---|---|
| Worker process wall and CPU | Interpreter launch through exit, including imports, all iterations/components, checks and journal/file I/O; CPU is child user + system time. |
| `runtime_import` | First canonical coverage import and its dependencies in each worker; excludes interpreter launch and this stdlib-only harness import. |
| `endpoint_reproduction` | Existing recipe owner, including configuration, session startup, runner, all eleven choices and trace checks. |
| `coverage_measure` | Entire `CanonicalDeploymentCoverage.measure(session=endpoint)` including admission, ordinary recipe/prefix reconstruction, all alternatives, persistence/checks and report assembly. |
| `report_json_roundtrip` | JSON encode/decode of the already materialized report payload, outside both report timers. |
| `coverage_from_payload` | Entire closed loader: complete fresh measurement and exact payload comparison; supplied endpoint and JSON report are already prepared. |
| Prepared component pass | Separate calls after all full iterations. Configuration, start, first advance, admission, prefix reconstruction, persistence encode, JSON checkpoint encode/decode, restore, artifact extraction and replay load/run have individual boundaries. |
| Per-occurrence components | Extra standalone `fork`; finite-set capture and coverage's actual finite probe owner; placement generator and production fresh-fork validator with current nine/ten generated/reference offsets and attempts (the retained five-offset campaign used five/ten for both; raw ceilings 64/10), accepted cap sixteen. Sets and results must exactly equal the authoritative row. |

`first_iteration` means the first workload in a fresh interpreter process. Imports
and endpoint preparation precede its first `coverage_measure`; the subsequent
`coverage_from_payload` is already warmed by that measurement. Later iterations
are repeats within the same process, not independent observations. All runs reuse
the same interpreter, package files and host; OS/page caches are neither flushed
nor claimed cold. Prepared components are already warm. Method costs include their
own nested operations: admission repeats startup/replay, validation includes
fork/restore/submission/checks, and prefix reconstruction includes forks/replay.
These costs and the extra fork diagnostic are **non-additive**. Do not subtract or
sum them to invent an exclusive decomposition of full-report cost.

## Evidence and interpretation

`measurement.json` is the machine-readable campaign record. It retains settings,
exact command, CPU model/count/affinity, guest memory and available cgroup limits,
OS/WSL kernel, interpreter/dependency versions, lock and harness SHA-256, Git
commit/tree/working diff and full engine manifest. The operator host note states
what is known outside the guest; hardware qualification remains provisional.
Each `process-NN` retains `attempts.jsonl`, stdout, stderr and its complete first
`canonical-report.json`. The final campaign embeds all parsed events and a partial
last journal line if termination interrupted a write. Started operations without
a finish remain incomplete; process exit status and budget/failure reason remain
visible. Records are operator diagnostics, not authenticated artifacts.

The committed final evidence lives in
[`canonical-deployment-costs-v1/measurement.json`](canonical-deployment-costs-v1/measurement.json)
and one complete
[`canonical-report.json`](canonical-deployment-costs-v1/canonical-report.json).
The campaign record embeds raw per-process events, stdout and stderr; duplicate
per-process report copies are unnecessary once their content hashes agree.

The original one-process pilot is retained **verbatim and separately** as
[`pilot-diagnostic.json`](canonical-deployment-costs-v1/pilot-diagnostic.json).
It completed within its declared 600-second wall/1,200-second CPU budgets and
reported 135.184 seconds for full measurement and 106.628 seconds for its
subsequent warmed closed reload. Its deterministic report hash agrees with the
canonical report. Its driver digest differs from the final driver, and the
predecessor source bytes were not saved. It therefore remains a diagnostic
observation, not a current-driver reproduction or one of the three qualified
campaign samples. No predecessor source bytes are reconstructed or inferred.
The pilot's original budgets, ordered raw operations, process outcome and logs
remain intact. Its statistics are not pooled with the final campaign.

The report content hash must agree across every successful reload, repeat and
process. The component pass rechecks exact generation/validation evidence,
checkpoint restore equality and `ReplayRunner.reproduced_exactly`. The harness
never patches production owners, supplies a new generator, changes acceptance,
or inserts clocks into actor context/state/replay/report fields. Existing report
fields listing pending Stage 2 obligations retain their original meaning.

Summaries group by operation, first/repeated process state, occurrence and
generated/reference role. They report sample count, mean, median, min/max and
sample standard deviation (undefined for one observation), and nearest-rank
empirical p90/p95. For three observations both percentiles equal the maximum;
they are observed sample statistics, not estimated population tail bounds. Successful completed
operations from failed attempts may appear in these descriptive summaries, but
the attempts remain failed/incomplete. Read outcomes and raw order first. Samples
within a process are dependent, and small samples provide no reliable tail or
confidence-interval estimate. There is no base/head speedup comparison, full-game
extrapolation, tactical quality claim or performance certification. Broader
useful reference qualification keeps Stage 2 open.
