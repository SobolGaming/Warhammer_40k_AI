# Contract 23 to 24: optional movement keywords

Order 53 uses existing finite Movement action and triggered-movement options.
Eligible options now contain `move_keyword_choice`, with the source rule ID,
descriptor ID, canonical unit ID, sorted living model IDs, explicit `selected`
boolean, and granted `keywords`. An unselected option has an empty keyword list;
a selected option grants MOBILE. Selected ordinary and parameterized reactive
options append `:move_keywords` to their engine-issued option ID. Finite reactive
paths retain deterministic enumerated IDs and display the grant in their labels.
Clients always select a pending option ID; they never generate these identifiers.

The original finite choice is copied into the movement proposal context and
retained across distance rerolls and rejected-path retries. Clients submit only
the existing witnessed proposal. Changing the source, model membership, chosen
keywords, actor or moving unit fails before queue pop. The keyword grant applies
to every living attached model only while validating that move; it does not become
an enduring model keyword or leak into a later Charge, Fight or Surge.

Completion sequencing captures one mandatory source-backed participant for a
selected grant. `move_keyword_roll_resolved` records its exact source occurrence,
choice, deterministic D6 evidence and direct Battle-shock update. A one makes the
unit Battle-shocked without a Leadership test or failed-test triggers. Existing
shared state cleanup and viewer projection apply. These movement decisions and
results are public gameplay information and use the shared viewer pipeline.

Movement capability and terrain path payloads require the nullable field
`horizontal_terrain_transit_height_inches`. This is a horizontal passage limit,
separate from climb/vertical-distance permissions and endpoint placement.

Metadata and command results/outcomes advance to `v24-contract`, persistence to
`session-persistence-v16-move-keywords`, and replay to
`replay-artifact-v18-move-keywords`. Old checkpoints and replays require their
original deployment; missing commitments or terrain fields are not inferred.
Released compatibility baselines remain immutable.
