# Contract 42 to 43: target-aware identical attacks

Order 103 implements the selected PRECISION FAQ: otherwise identical attacks can
form one group when the canonical target rules unit contains no CHARACTER. Targets
containing CHARACTER keep the PRECISION distinction. Physical weapon contributions,
source profiles, observer/range/visibility and all other effect distinctions remain.

Every emitted and persisted `GatheredAttackGroup` now requires the Boolean
`target_has_character`. The value describes target membership at grouping, and is
part of deterministic group identity. Current pending choices are checked against
current canonical target context before mutation. Selected groups and historical
random-profile scopes retain their recorded context after casualties; restoration
never guesses it from a later battlefield or defaults a missing value to false.
Unresolved replacement pools use their newly selected target before grouping.

This required nested property and changed group identifiers require major 43 even
inside the existing open-JSON decision/event envelopes. Metadata and command
result/outcome families advance to v43. Persistence advances to
`session-persistence-v35-target-aware-attack-groups`, binding Contract 43 and the
exact runtime. Replay advances to `replay-artifact-v36-target-aware-attack-groups`.
Finite submissions, decision-view/event/projection envelopes and all other family
versions retain their existing shapes. Clients must regenerate, discard cached
requests and group IDs, and fetch fresh engine-authored pending choices.

Older saves and replays require their exact original runtime; no conversion or
missing-field inference is provided. Released baselines through 42.0 remain
immutable. Hosted deployments must retain 42.x through at least 2027-10-02 and one
released 43.x minor line, whichever is later. Earlier retention obligations remain.
The reference server supports one major and provides no parallel old endpoints.
