# Contract 15 to 16: Critical-hit authority

Contract 16 implements the App-data v931 critical-hit and Snap Shooting FAQs.
A source-authorized lowered critical threshold makes an unmodified qualifying
roll both successful and critical despite worse ordinary skill. Snap retains
its unmodified-six requirement unless the source explicitly overrides that mode.
Modifiers never turn an ordinary raw face into a critical hit.

Every nested HitRoll now requires `critical_threshold` and
`threshold_source_ids`. The record validates its current dice face, capped
modifier trace, failed-face floor, critical flag and success flag together.
Lethal Hits and Sustained Hits consume the same engine-owned result. Clients
must render these values rather than assuming that only a raw six is critical.
The existing public JSON event envelopes and decision/proposal families remain.
Shared viewer-scoped redaction still controls every projection and event delta.

Metadata and command result/outcome families advance to `v16-contract`.
Operator persistence advances to `session-persistence-v8-critical-hits` and
replay exports to `replay-artifact-v10-critical-hits`. New source and generated
IR hashes are part of the runtime identity. These changes require regeneration
of clients and cached session data.

The reference server supports major 16. Old checkpoints and replay artifacts
remain usable only with their matching old deployment. Missing thresholds and
source context cannot be inferred, and no automatic migration is provided.
All released compatibility baselines remain immutable.
