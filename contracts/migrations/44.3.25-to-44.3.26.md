# Contract 44.3.26

An accepted Combat Disembark applies direct Battle-shock to its canonical
surviving rules unit after hazard damage and any Feel No Pain continuation finish.
The shared status owner supplies Objective Control, Stratagem and Action
restrictions, without a fabricated Leadership test or test-outcome trigger.

The new `combat_disembark_battle_shock_applied` event binds `game_id`,
`battle_round`, `player_id`, `unit_instance_id`, `source_rule_id`, accepted
`request_id` and `result_id`, `disembark_event_id`, `hazard_event_id` and
`state_update`. Reconstruction validates accepted setup and completed hazard
authority. A destroyed passenger records `not_required`; existing shock records
`already_battle_shocked` without a duplicate status or interruption.

Combat's restriction marker now reads `battle_shocked_until: "until_cleared"`.
The charge prohibition still ends with the current turn. Authoritative shock
persists into the next ordinary own Command Battle-shock step, even above half
strength; a failed required test retains it and a successful test clears it.

Existing decision families, proposal shapes, generic event envelopes and viewer
scoping cover this event. Runtime identity changes, so prior-runtime saves and
replays require their original producing runtime. Historical captures remain
unchanged; no compatibility shim migrates them. Emergency Disembark status
integration remains a separate scope.
