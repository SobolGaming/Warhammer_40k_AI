# Contract 22 to 23: Surge targets and phase movement authority

Surge uses the existing triggered-movement decision family and `surge_move`
proposal kind. Finite unit options commit a closest enemy with IDs shaped as
`surge:<rules-unit-id>:target:<enemy-rules-unit-id>`. Equidistant enemies remain
separate options. Clients select an engine-issued ID and never supply or change
the target in a path proposal. The target commitment survives distance rerolls,
rejected paths and retries. Surge has no Take to the Skies variant.

Triggered movement now emits `aircraft_movement_policies`, keyed by component
unit ID, instead of a single `aircraft_movement_policy`. Attached units retain
each component's effective policy in their shared movement record.

Eligibility checks the recorded granting trigger, current Battle-shock and
Engagement, and all accepted movement in the current player's phase occurrence.
Accepted endpoints carry `surge_target_unit_instance_id` and per-model
`surge_model_endpoints` evidence. Each model must engage that target where
possible, otherwise achieve a proved closest endpoint; other enemy Engagement
is forbidden. An unresolved geometric search returns an explicit invalid
diagnostic and preserves the battlefield, followed by a retry request.

GameState requires `phase_movement_history`, binding accepted moves to source
events, round, actual turn owner, phase, canonical unit and physical model IDs.
Surge does not consume a Normal-move record. It prohibits every later move in
the same phase occurrence, including moves by surviving attached components.
The ledger is internal; existing shared viewer redaction applies to decisions
and events. Restore authenticates history and endpoint evidence; replay includes
recorded rejected proposals and their exact retry event stream.

Metadata and command results/outcomes advance to `v23-contract`, persistence to
`session-persistence-v15-surge-authority`, and replay to
`replay-artifact-v17-surge-authority`. Use old deployments for old checkpoints
and replays. Missing target commitments and movement history cannot be inferred.
Released compatibility baselines remain immutable.
