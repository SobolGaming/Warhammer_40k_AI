# Contract 45 to 46

Contract 46 separates private randomness and authoritative history from the
player-facing decision interface. Deploy updated clients with the updated server;
retain 45.x through at least 2027-11-06 and one released 46.x minor line, whichever
is later. Existing artifacts remain available to their matching old runtime.

## Randomness and restoration

Operator game configuration requires `private_rng_seed`, a 64-character lowercase
hexadecimal secret independent of the public game ID. Fresh Python construction
can generate it. Persist the exact seed and the engine-owned tactical draw
sequence; current restoration rejects missing, mismatched or malformed authority.
Do not send operator configuration, persistence or replay payloads to policies.
They retain private seed information and are privileged operator artifacts.
There is no automatic reseeding or ordinary old-save migration. The separately
selected, exact-artifact A32 audit recipe is documented in
[its maintained profile](../../docs/A32_HISTORICAL_CHECKPOINT_RECONSTRUCTION.md).

## Player identifiers and commands

Use the exact request and option IDs issued in the submitting player's current
projection. Viewer aliases are scoped to the public game and viewer role/player;
never construct them or copy another viewer's IDs. They include derived runtime
references and ordinal-bearing unit/model IDs. Typed display-map keys preserve
joins. Public game, actor, player and army IDs and stable catalog IDs remain public.
Declared engine label/message/reason text renders counter references through the
same map. Authoritative replay IDs remain unchanged.

Copy `expected_session_revision` from that same viewer's metadata or projection.
For non-omniscient viewers it is the visible event count; one accepted command
can advance it by several events. Do not increment it locally or use the
administrator's revision. Hidden opponent-only work does not advance it.
Non-omniscient `last_activity_at` is null. Wrong actors remain forbidden before
revision conflict details are considered.

Direct adapter event cursors count visible events. HTTP cursors remain opaque,
authenticated tokens: preserve and return them unchanged. Retention is measured
per visible stream, and hidden-only progress preserves the viewer's existing
cursor. Snapshot retention is a bounded union of administrator and viewer
boundaries. Old cursor schemas are rejected.

Python policy/UI/headless producers use `submit_viewer_option` and
`submit_viewer_parameterized_payload`. Trusted host/replay methods keep their
explicit authoritative namespace. The server resolves issued aliases and still
uses the same engine validator, mutation, decision records and replay. Unissued,
wrong-actor, malformed and stale submissions never select a substitute action.

Regenerate the TypeScript client and use the current published family versions.
The bundle's schemas, examples and 46.0.0 baseline define their exact wire shapes.
