# Contract 25 to 26: duplicated ability instances

Order 56 implements 24.02 controlling-player selection. Weapon instance IDs are
physical source occurrences, replacing descriptor IDs in
`selected_weapon_ability_ids`. The engine groups duplicates before evaluating
numbers or target keywords, including Anti across different keywords. Each
physical weapon selects one instance per duplicated family at Select Weapons.
Shooting and melee expose nested `select_weapon_ability_instance` finite requests
with complete `selection_context` inventories. Melee declarations gain optional
`selected_weapon_ability_ids`; omission is valid only when no duplicate exists.
Use the emitted IDs without constructing or interpreting them.

The engine commits the selected immutable profile and source context to attack
pools. Target redirection retains that selection, including conditional sources
that no longer apply. It does not choose a replacement source or add later
grants. Missing, stale, forged, conflicting and wrong-owner choices fail before
mutation. Split melee allocations share the complete offered inventory and
evaluate the selected source for each target.

`select_core_ability_instance` is a registered finite decision. It records the
selected physical occurrence and opportunity for persistent Core families.
Native and applicable granted sources remain separately identifiable. Setup
choices are secret to the controlling player through the shared redaction module,
using `visibility_source: "core_ability_instance"` on owned secret events.
Core choice events and optional unit `core_ability_selections` authenticate
restore; optional `core_keyword_sources` preserves repeated Deep Strike grants.

Feel No Pain retains its source-choice decision. Duplicated mandatory Deadly
Demise uses `select_destruction_reaction` with
`selection_kind: "duplicated_deadly_demise_instance"`, complete destruction
context, and exactly one mandatory source option; there is no decline option.
Scouts options preserve every universally shared distance plus the lowest
unshared distance. Dedicated transports use the same cargo calculation.

Metadata and command result/outcome schemas advance to `v26-contract`, persistence
to `session-persistence-v18-ability-instances`, and replay to
`replay-artifact-v20-ability-instances`. Older saves and recordings require their
original deployment. Source occurrence IDs also change native damage-ability
materialization, and request payload changes may change deterministic dice
streams because recorded history participates in RNG identity.

Only major 26 is supported by this runtime. Retain 25.x through at least
2027-09-17 and one released 26.x minor line, whichever is later. Earlier retention
obligations remain. Released baselines are immutable. No compatibility repair
or descriptor-ID fallback is provided.
