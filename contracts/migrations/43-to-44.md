# Contract 43 to 44: current canonical model membership

Contract 44 requires `rules_unit_instance_id: string | null` on every model in
`battlefield_view.authoritative.models_by_id`. The battlefield family is now
`battlefield-view-v5-rules-unit-membership`. Physical `unit_instance_id`, model
identity, geometry, pose and state retain their existing meaning.

To draft a Charge, read the current proposal's canonical `unit_instance_id`,
select projected models whose `rules_unit_instance_id` matches that actor and
whose `state` is `placed`, and build a complete `PathWitness` from those models'
current poses. Their physical component is each model's `unit_instance_id`.
Submit the original canonical actor, committed target subset and request identity;
the request's movement budget and engine validation remain authoritative.
Do not derive component membership from identifiers or use a projection hash as
the proposal's `spatial_context_hash`.

Membership is recomputed from current engine rules units for each projection.
Split successors therefore replace the old actor mapping. Casualties and removed
models retain lineage identity but cease to be `placed` witness members. The
owner receives every visible model in its actor; no additional model is disclosed
to other viewers. During unresolved simultaneous formation declarations,
opponent/public models have a null canonical ID, including ordinary units, so
the new field cannot reveal an attachment or split choice. After reveal the
current mapping is public under the existing visibility rules.

The same projection join is available for Move, Pile In and Consolidate. Scout
and deployment retain their existing explicit component/model request inventories.
This change adds no new movement permission and changes no witness validation.
Missing/foreign models, physical aliases submitted as canonical actors, stale
starts, wrong targets and invalid paths still fail through the shared engine path.

The generated TypeScript client consumes the attached Charge projection example;
facade tests build accepted ordinary/attached Charges from public data and verify
retry, save/load, split reveal and physical membership freshness. Session wrapper
metadata/result/outcome tags advance to `v44-contract`; persistence's external
contract pin becomes `44.0.0`, with no lifecycle state format change.

Retain the 43.x deployment through at least 2027-10-02 and one released 44.x
minor line, whichever is later. Old checkpoints/replays require their original
runtime. The immutable 43.0.0 compatibility baseline remains committed.
