# Contract 41 to 42: optional ranged targets

Order 95 lets a selected unit submit an empty ranged declaration, or select a
physical weapon while explicitly declining its target with
`target_unit_instance_id: null`. Regenerate clients and discard cached requests;
clients must no longer assume that every selected weapon produces an attack pool.
Existing physical identity and source-instance choices remain mandatory.

Requests with duplicated weapon abilities expose `targetless_weapon_candidates`
with nested source-instance choices. Accepted events and attack executors carry
optional `weapons_without_attacks` inventories containing `declaration` and
`source_profile`. These preserve Hazardous and One Shot while attack participation,
Hidden loss and after-shot rules apply only to actual attacks. An empty declaration
has no selected weapons but retains mandatory selection-created obligations through
the shared executor. An explicit empty selected inventory differs from an omitted
inventory. Automatic no-candidate terminals remain alternative authenticated origins
for their own pending selection obligations.
All submissions still use the common facade and engine-owned mutation path.

The canonical nullable target replaces the former identifier-only schema and
changes consumers' mutation semantics, requiring major 42. Metadata and command
result/outcome envelopes advance to v42; persistence advances to
`session-persistence-v34-optional-ranged-targets`, binding Contract 42 and the exact
runtime identity. No missing selection or target is inferred. Older saves and
replays remain usable only with their exact original runtime.

Hosted deployments must retain 41.x through at least 2027-09-28 and one released
42.x minor line, whichever is later. Earlier retention obligations remain in force.
The reference server does not provide content negotiation or parallel old endpoints.
See the Order 95 adapter contract for validation, viewer scope and replay semantics.
