# Contract 14 to 15: Rules Sequencing

Contract 15 changes engine-owned rule ordering under Core 01.03–01.03.02.
The active player resolves mandatory rules, then optional rules; the opposing
player does the same. Each owner chooses within their tier. Newly triggered
rules wait for the original batch to finish. Source-explicit mission and Scout
ordering retain their own constraints. Selecting a unit to move, shoot or fight
temporarily changes active-player authority; turn ownership remains separate.

Clients continue to select an emitted finite option or submit an engine-issued
parameterized proposal. They must not cache an assumed rule-family order, infer
the decision actor from turn ownership, or manufacture sequencing option IDs.
Hidden participants and private trigger history remain viewer-scoped through the
shared redaction service, including derived metadata and event deltas.

Metadata and command result/outcome families advance to `v15-contract`.
Operator persistence advances to `session-persistence-v7-sequencing` and replay
exports to `replay-artifact-v9-sequencing`. Persisted sequencing now includes
original batch membership, selected/completed rules, deferred triggers and source
authority. Primary scoring evidence and boundary lifecycle rows use v2 and
require `scoring_player_id`. Separate owners may commit against one physical
boundary in the selected rule order; the commit history authenticates the mission
state at that exact event, including Actions and optional mission choices.

The minimal live Normal Move example includes empty selected movement-grant
inventories. Other movement requests carry their actual engine-selected source
grants in opaque proposal context. Adapters must preserve that context and submit
against the current request; they do not apply those grants themselves.

The reference server supports only major 15. Regenerate client models and discard
cached major-14 session/request payloads. Existing major-14 checkpoints and replay
artifacts are rejected; missing owner, trigger or source history is not inferred.
Keep a separate matching major-14 deployment if old sessions must finish before
upgrading. There is no automatic checkpoint migration. Released compatibility
baselines remain immutable.
