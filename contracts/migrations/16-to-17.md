# Contract 16 to 17: phase-end Fire Overwatch

Contract 17 implements Order 45 and the reviewed 15.08/15.09 source text.
Fire Overwatch now has one optional opportunity per opponent Movement phase end,
even when no enemy moved or was set up. Its window ID is
`fire-overwatch-end-movement-round-{round:02d}-player-{player}`. The trigger
payload contains `timing_window_id` and `trigger_window`; it no longer emits a
moved-unit identifier, eligible movement classes, or a triggering enemy.

Discovery checks current shooter presence and basic eligibility plus the presence
of a source-permitted enemy. The optional proposal can be declined without
resolving every potential shot; exact range and visibility are validated when a
shooter is submitted, before CP spend.

The existing parameterized Stratagem decision selects an eligible friendly
unengaged non-TITANIC rules unit. The subsequent canonical shooting declaration
chooses one eligible visible enemy within 24 inches of that rules unit. Every
weapon declaration must target that same enemy using the engine-emitted Snap
shooting type. Source protections, target restrictions, weapon range, current
model-group presence and visibility remain authoritative. Candidates with no
permitted forced shooting type are invalid and carry
`forced_shooting_type_unavailable`. No new decision or proposal family is added.

Clients must discard cached movement-trigger assumptions, render the current
candidate choices, and pass through the exact issued Stratagem context. The
engine rejects drifted source context and stale or invalid targets before queue
pop or mutation. CP is spent once after shooter validation; the shared attack
sequence and reaction frame complete before phase continuation. The raw-six hit
policy, source-authorized threshold exceptions, no-hit-reroll rule and temporary
post-Snap Action lock retain their shared owners. Viewer scoping is unchanged.

Metadata and command result/outcome families advance to `v17-contract`.
Operator persistence advances to `session-persistence-v9-phase-end-overwatch`
and replay exports to `replay-artifact-v11-phase-end-overwatch`. Source-package
and runtime build hashes change. Regenerate clients and fetch fresh session data.

The reference server supports major 17 only. Old checkpoints and replay artifacts
remain usable only with their matching old deployment. No automatic migration
or missing source-context inference is provided. Existing deployment-retention
obligations remain in force, and all released baselines remain immutable.
