# Contract 40 to 41: modifier occurrence identity and subset choices

Order 93 retains each source operation until the engine has applied the owning
player's `select_modifier_ignores` choices. A permission without a typed subset
covers model characteristics, equipped-weapon characteristics and rolls. Explicit
subsets remain restrictive; a Save characteristic permission does not implicitly
cover the distinct invulnerable-save characteristic.

The finite request binds an occurrence ID, typed unit/model/weapon subject,
source operations, current source permission evidence and continuation context. Clients choose an emitted option ID to keep or ignore the next
operation or all remaining operations. Partial choices advance a deterministic
prefix until the occurrence is complete. Clients must not construct operation
IDs, infer choices from the sign of a modifier, or reuse an occurrence's selection
for a later attack or roll. The engine rebuilds and validates pending authority
before accepting a choice; malformed or stale submissions leave the queue and
state unchanged. The decision family is owner-only; shared redaction removes the private restore
origin and internal save-selection snapshots from viewer payloads.

Attack occurrences require `source_context.permission_attack_context`, containing
the actual attacking unit/model, target unit, subject role, phase, full weapon
profile and nullable resolved Strength/Toughness. Creation and before-pop
validation use the same typed context, authenticated by independent historical
reconstruction. Defensive permissions use the target role. Restrictions needing
unavailable target/weapon/comparison facts raise an explicit unsupported-context
error instead of being silently treated as inapplicable. Defensive source-unit
Starting/Half Strength restrictions are likewise unsupported until the permission
source unit can be independently authenticated. Existing finite option
submission and owner-only redaction cover this nested engine-owned evidence.

Mission Action requests and options require the nullable
`objective_control_modifier_scope_id`. Their boundary checkpoint omits this
field when no modifier scope exists; a present checkpoint scope must be a
nonempty string and participates in the checkpoint content hash.

Fixed `CharacteristicValue` and fixed-distance `RangeProfile` payloads may carry
`modifier_trace`: `characteristic`, original `source_value`, source-linked
`modifiers`, `bounded`, and `ignored_modifier_ids`. The engine verifies the
reported numeric result against this trace. Range trace and `random_value` are
mutually exclusive. Weapon Attacks and Damage retain their original fixed or
dice source. When operations exist, the three fields `source_fixed_value`,
`modifiers`, and `ignored_modifier_ids` occur together; random profiles have a
null fixed source. Modifiers remain distinct from the intrinsic dice expression.

Save options now require `characteristic_trace`, `armor_penetration_trace`,
`roll_modifiers`, and `ignored_roll_modifier_ids` alongside the existing save
fields. The two traces may be null; the roll inventories may be empty. These
engine-authored nested decision/event values preserve source operations without
allowing adapters to submit or modify a save profile. Canonical proposal schemas
and the generated client carry the corresponding source operation evidence for
weapon profiles, including borrowed Firing Deck profiles.

Metadata and command result/outcome families advance to v41. Persistence uses
`session-persistence-v33-modifier-occurrences`; replay uses
`replay-artifact-v35-modifier-occurrences`. Operator-only modifier evaluation
origin evidence permits authenticated reconstruction of historical choices.
It is not a viewer projection field. Existing finite submission envelopes,
parameterized proposal kinds and ordinary game-view shapes are unchanged.

Older saves and replays require their exact original runtime. Retain 40.x through
at least 2027-09-27 and one released 41.x minor line, whichever is later. There is
no conversion that invents lost modifier identities or unrecorded choices.

Random profile values additionally preserve optional `ignored_modifier_ids` while
retaining all source `modifiers` and the original dice expression. Re-evaluation
applies the recorded subset to the existing raw result. Evaluated random values
require integer `evaluation_raw` together with `evaluation` and `evaluation_id`.
The raw result remains available under symbolic dash/star replacements and is
authenticated against the historical dice; missing source evidence is rejected.
SaveOption payloads
include required `inherent_roll_modifiers` alongside `roll_modifiers`; incoming
AP and applicable cover contribute distinct source operations to the saving
throw inventory.

A source-limited reduction carries optional integer `result_floor` on its
`Modifier` operation. The field is absent on unrestricted operations. It is
part of the single source effect: clients cannot select the reduction and its
limit independently. The floor limits that reduction's contribution without
worsening an already lower value or capping other unrestricted reductions.

The first-failed-save Damage-to-zero replacement participates as a sourced
`SET 0` Damage operation. Ignoring it records
`failed_save_damage_replacement_ignored` with the same source/occurrence fields
as `failed_save_damage_replaced`, consuming that first occurrence.
